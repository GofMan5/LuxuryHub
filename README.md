# LuxuryHub

Десктоп-приложение премиум-маркетплейса: **Go-бэкенд** + **нативный клиент на
GPUI-CE** (Rust). Репозиторий — заготовка архитектуры, а не готовый продукт:
здесь есть два собирающихся каркаса, соглашение о структуре и короткое описание
решений, чтобы дальше наращивать функциональность.

## Статус

| Часть | Состояние |
|---|---|
| `backend/` | HTTP-сервер на stdlib: `/healthz`, `/version`, конфиг из env, graceful shutdown, тест |
| `desktop/` | Окно 1200×800 на `gpui-ce 0.3`, сайдбар и рабочая область, дизайн-токены |
| `docs/architecture.md` | Слои, поток запроса, границы модулей, план по фазам |

Никаких «настоящих» фич, БД и protobuf-контрактов пока нет — это следующий шаг,
и он описан в `docs/architecture.md`.

## Стек

- **Go 1.25**, только стандартная библиотека на старте (`net/http`, `log/slog`).
  Курсорная пагинация, валидация и доменные типы — свои, без тяжёлых фреймворков.
- **Rust** (edition 2024) + **GPUI-CE 0.3** — форк GPUI от Zed, Apache-2.0.
  Пакет на crates.io называется `gpui-ce`, библиотека внутри — `gpui`;
  платформенный слой — пакет `gpui_ce_platform` (алиас `gpui_platform`).
- Windows 11 x64 — целевая платформа. macOS/Linux не проверялись.

## Запуск

Бэкенд:

```powershell
cd backend
go run ./cmd/luxuryhubd
# http://127.0.0.1:8080/healthz
```

Клиент (первая сборка GPUI занимает несколько минут):

```powershell
cd desktop
cargo run -p lh-app
```

Или через `make`: `make backend-run`, `make desktop-run`, `make desktop-watch`, `make check`.

Конфигурация бэкенда — переменные окружения с префиксом `LUXURYHUB_`:
`LUXURYHUB_ADDR` (по умолчанию `127.0.0.1:8080`), `LUXURYHUB_ENV` (`dev`/`prod`),
`LUXURYHUB_LOG_LEVEL` (`info`).

## Живая разработка

GPUI — нативное приложение, а не веб-страница: код на Rust нельзя подменить в
уже запущенном бинарнике. Горячая замена (`hot-patching`) в `gpui-ce 0.3`
существует, но завязана на инфраструктуру Dioxus (`subsecond` + devtools-сервер)
и для стороннего приложения не собирается как рабочий цикл — на неё не стоит
рассчитывать. Поэтому скорость дают два других уровня.

**1. Тема — без пересборки.** `desktop/theme.ini` читается клиентом на старте и
перечитывается во время работы: сохранил файл — окно перекрасилось примерно за
200 мс, без перезапуска и потери состояния.

```ini
background     = #0E0F12
surface        = #13151A
surface_raised = #1A1D24
border         = #262A33
text           = #E9E4DA
text_muted     = #9A958C
accent         = #C8A24A
accent_soft    = #2A2415
```

Пропущенные ключи берутся из встроенной палитры, неизвестные и опечатанные
цвета печатаются в stderr и не ломают окно. Путь переопределяется переменной
`LUXURYHUB_THEME` (release-сборка читает тему только по ней).

**2. Код — пересборка и перезапуск.** `make desktop-watch` собирает workspace
через `cargo-watch` и перезапускает клиент на каждое сохранение `.rs`. Это
инкрементальная сборка без зависимостей, поэтому после первой сборки цикл
занимает секунды; окно при этом закрывается и открывается заново, состояние
навигации сбрасывается. Нужен установленный `cargo-watch`
(`cargo install cargo-watch`).

Что это значит на практике: цвета, отступы-константы и тексты в `lh-ui` можно
крутить на живом окне правкой `theme.ini`; всё, что добавляет или меняет
элементы, требует сохранения файла и одной пересборки.

## Принципы

1. Один бинарник бэкенда, несколько режимов запуска (`api`, `worker`, `migrate`).
2. Клиент — нативное приложение: сеть, диск и токены не касаются UI-потока.
3. Деньги — целые минорные единицы, никогда не `float`.
4. Контракт клиент↔сервер появляется раньше фич и живёт в одном месте.
5. Любая зависимость должна окупаться: сначала stdlib и платформа.
